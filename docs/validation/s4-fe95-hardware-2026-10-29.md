# S4 FE95 实机发现

2026-10-29，组合固件 `8df62b6`，云端运行 40849032592。用户授权刷入该组合诊断版本；原工程保持不动，板上前一程序已两次备份且摘要一致。设备地址、个人心率和原始串口日志不上传仓库。

## 操作与结果

用户打开 S4 心率共享并临时关闭手机蓝牙，未解绑或重置手表。开发板收到目标 S4 的广播，手动指定核实后的设备地址和 random 类型连接成功。未要求配对、未写 GATT、未发应用或快门命令。

服务发现得到 FE95，范围 `0x0012..0x001a`；同一 GATT 表还包含心率服务 180D，范围 `0x0038..0x003b`。以下为实际发现值，后续实现仍需重新发现，不能硬编码 handle：

| 服务/特征 UUID | Value handle | Properties | 属性含义 |
| --- | --- | --- | --- |
| FE95 / 0050 | 0x0014 | 0x02 | Read |
| FE95 / 005E | 0x0016 | 0x14 | Write Without Response + Notify |
| FE95 / 005F | 0x0019 | 0x14 | Write Without Response + Notify |
| 180D / 2A37 | 0x003a | 0x10 | Notify |

UUID 为发现 API 返回的 16-bit UUID 表示。Properties 只是特征属性，不能推断加密、认证或访问权限已满足。005E/005F 与已记录 S4 BLE companion 示例的候选通道吻合；尚未订阅它们或完成认证。

## 对组合架构的影响

本次 FE95 与 HRS 位于同一连接的服务表中，后续应优先评估共用一条 S4 BLE 连接承载心率和应用消息，再与 Action 4 保持另一条连接。当前组合诊断代码仍有分开的心率/诊断连接所有者，尚未实现共用连接或证明手表允许两个客户端连接。连接预算 3 不代表实机已验证三连接。

开发板主流程仍运行原踏频待机策略；诊断扫描及连接未被心率待机关闭。没有踏频或码表转发的本轮实测，所以不能把旧工程的验收自动转移到组合固件。

下一阶段为：读取配套能力、确认用户合法配对凭据的获取方式，实现 SAR/认证及带 ID 的应用消息回环。未经确认不更改手表绑定、不重置设备、不采用公开示例的他人密钥。
