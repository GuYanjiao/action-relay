## 优先修复

### P1：停止确认后，手表仍接受旧状态和退休会话

位置：`watch/src/common/relayController.js:115-123,137-146`。

- `seq` 只在 session 相同时比较；新 session 到达后，迟到的旧 session 又被当作新会话接受，没有退休会话集合或其他可靠的新会话握手。
- confirmed result 带有 revision，但接收端不使用它建立最低可接受版本。清空 lastStatus 后，仍可接受序号比最后一次收到的 status 大、但 revision 小于确认结果的旧快照。
- 本次用原控制器和原测试夹具补充复现，两个场景均实际出现状态回退：
  1. old-session/seq100/录像 → new-session/seq101/停止 → 迟到 old-session/seq99/录像，最终界面重新显示录像。
  2. session-a/seq10/revision5/录像 → stop → confirmed/revision6 → 迟到 seq11/revision5/录像，最终界面重新显示录像。
- 修复应包含退休会话拒收、确认后的版本下限，以及刷新/断线/重新显示页面时的规则。不能通过盲目把 recording 置为 false 代替新鲜相机状态。

### P1：发送超时后的旧回调会结束下一次发送

位置：`android/src/cn/local/actionrelay/XiaomiWatchBridge.java:177-192`。

- send A 超时后 finishSend 会启动 B；如果 A 随后回调成功，因 nodeId/generation 仍相同，它又会进入 finishSend，移除 B 的超时、清除 sending，再启动 C。
- 这会破坏发送泵的状态隔离，可能让旧状态和结果交错。generation 是服务运行代数，不能区分同一代里的 A/B/C。
- 应增加每次发送的唯一 token，回调和超时只能完成自己的 token；明确处理服务重启、节点切换、断线，以及超时后旧 SDK 任务仍在运行的情况。
- result 目前使用 addFirst，包含 accepted 和 terminal，形成倒序且未设容量上限。请建立有界队列、区分终态与受理状态，避免迟到 accepted 压过 confirmed。
- 本项依据代码路径确认，尚未使用真实 SDK 注入延迟回调验证。

### P1：运行中开启 GPS 不生效

位置：`RelayHub.java:117-119,138`；`RelayService.java:33`。

- GPS 开关调用 setGpsEnabled(true)，只改布尔值和偏好；随后启动 RECONFIGURE 服务。
- Service 没有专门执行重新配置，只再次调用 hub.start()。
- 此时中转已 enabled，start() 第一行立即返回，gps.start() 永远不会执行。
- 典型路径正是“先开中转，再在 UI 开 GPS”。GPS 可能只在记住开启意图、停止并重新开启中转后才启动。
- 应在前台服务类型提升成功后显式同步定位生命周期，关闭/权限拒绝/服务重配都覆盖。加入从关闭到开启、关闭再开启的回归检查。

### P2：冷启动记忆重连绕过连接上下文初始化

位置：`RelayHub.java:62-63,78,129-138`。

- reconnectRememberedCamera() 直接调用 ble.connect，没有初始化 selectedAddress、验证码和连接上下文。
- 新进程 selectedAddress 为空，握手读取 `paired_` 而不是 `paired_<相机地址>`；成功时还会把空 selectedAddress 写回 camera_address。
- 应让普通连接和记忆重连共用一次明确的连接初始化；对已选相机、授权拒绝、主动停止、取消延迟重连分别处理。
- forgetCamera() 也未清理 camera_address/camera_name，遗忘后下次仍可能尝试重连。

### P2：快捷磁贴与状态表达还需补齐

位置：`RecordingTileService.java`；`XiaomiWatchBridge.java:164-166`；`relayController.js` 定时器。

- 磁贴没有锁屏解锁处理；update 只在开始监听和点击时调用，面板保持打开时不会随相机状态持续更新。
- requestAdd() 仅尝试一个设置 Intent，失败后进入通用系统设置，未实现可靠的添加磁贴入口。
- watchConnected 依赖最近 15 秒的手表上行消息，但手表定时器不定期发送心跳/状态请求。正常接收手机推送的空闲手表，仍可能在手机 UI 上被显示为未连接。
- GPS speed 使用 abs(north)+abs(east)，不是水平速度，应改为平方和开方；GPS phase 名称也需与两端 UI 的状态枚举统一。
