# 心率 ANT+ 与相机中转组合固件

目标是在同一块 Pro Micro nRF52840 上保留手表心率 → ANT+、踏频触发及待机行为，并加入 S4 快应用 → Action 4 控制。两项功能需要链接为一个应用，不能依次刷入两个 UF2。

## 当前阶段

已导入用户实测工程的固件源码基线，来源提交及逐文件摘要见 `upstream.json`；原始 `watch-hr-ant-relay` 仓库不修改、不覆盖。保留原时钟、ANT 设备号 4242、踏频唤醒、心率过期处理和分区。组合副本先将 BLE 连接预算设为 3，并使心率连接回调及断开操作只处理自身连接，避免影响将来的相机或配套连接。

**这仍是组合开发基线，相机控制尚未接入，不能作为双功能完成版刷写。** `../protocol/miwear_auth.c` 参与编译但尚未从运行流程调用，不含用户 AuthKey。已有独立 probe 只作为协议诊断工具，不替换板上 ANT+ 应用。

## 构建与验证

云端使用与实测心率工程一致的 NCS 3.2.4、ANT Add-on 2.1.1 及官方工具链镜像。该 SDK 配对符合 [ANT 官方兼容表](https://ant-nrfconnect.github.io/doc/compatibility.html)；没有因上游 Zephyr 更新而单独升级其中一个组件。本地不编译，不自动刷写。

保留显式静态分区表，云端对 UF2 地址、芯片 family、初始栈及复位入口进行检查。产物和元数据会明确标记相机控制未实现、组合真机未验收。

## 待完成的组合工作

1. 统一 BLE 扫描调度。原心率流程的待机不能关闭配套或相机所需的扫描；多连接回调隔离只是第一步。
2. 从实物确认 FE95 的完整服务与特征权限，再实现用户设备认证、SAR、加密和应用消息往返。
3. 接入 Action 4 控制，保留启停确认与断线不重放快门的规则；不能让心率踏频待机条件阻止用户控制相机。
4. 联调心率/踏频/相机共存、无线调度、资源占用及掉线恢复，再考虑刷写和功耗优化。
