# 心率 ANT+ 与相机中转组合固件

目标是在同一块 Pro Micro nRF52840 上保留手表心率 → ANT+、踏频触发及待机行为，并加入 S4 快应用 → Action 4 控制。两项功能需要链接为一个应用，不能依次刷入两个 UF2。

## 当前阶段

已导入用户实测工程的固件源码基线，来源提交及逐文件摘要见 `upstream.json`；原始 `watch-hr-ant-relay` 仓库不修改、不覆盖。保留原时钟、ANT 设备号 4242、踏频唤醒、心率过期处理和分区。组合副本先将 BLE 连接预算设为 3，并使心率连接回调及断开操作只处理自身连接，避免影响将来的相机或配套连接。

**这仍是组合开发基线，相机控制尚未接入，不能作为双功能完成版刷写。** `../protocol/miwear_auth.c` 参与编译但尚未从运行流程调用，不含用户 AuthKey。已有独立 probe 只作为协议诊断工具，不替换板上 ANT+ 应用。

## 组合内的只读诊断

新增 USB 文本命令，每条以回车结束；原来的单字节 `B` 进入启动盘命令保留。输入每轮最多处理 32 字节，不在 ANT 主循环等待整行。诊断不主动配对、不写 GATT、不控制相机，不自动选择附近设备。

```text
watch scan
watch stop
watch connect AA:BB:CC:DD:EE:FF random
watch services
watch chars
watch disconnect
```

只连接用户核实的实际手表地址，类型按广播中的 public/random 选择。扫描候选条件为 S4 名称或 FE95，条件本身不能证明设备身份。等连接成功再枚举服务，等完成后再枚举特征，核对完整 UUID 与权限。该命令集尚待组合固件的云端编译和实机检查，不能将心率转发成功推断为 FE95 可用。心率仍按原踏频策略触发，诊断需求独立登记。

## 构建与验证

云端使用与实测心率工程一致的 NCS 3.2.4、ANT Add-on 2.1.1 及官方工具链镜像。该 SDK 配对符合 [ANT 官方兼容表](https://ant-nrfconnect.github.io/doc/compatibility.html)；没有因上游 Zephyr 更新而单独升级其中一个组件。本地不编译，不自动刷写。

保留显式静态分区表，云端对 UF2 地址、芯片 family、初始栈及复位入口进行检查。产物和元数据会明确标记相机控制未实现、组合真机未验收。

## 待完成的组合工作

1. 统一 BLE 扫描调度。已加入按功能登记需求的共享扫描器、广播缓冲恢复与单条有界连接发起队列，并让心率流程通过它扫描；正在进行云端验证。原心率流程的待机只撤销自身需求，不关闭其他功能的扫描。
2. 从实物确认 FE95 的完整服务与特征权限，再实现用户设备认证、SAR、加密和应用消息往返。
3. 接入 Action 4 控制，保留启停确认与断线不重放快门的规则；不能让心率踏频待机条件阻止用户控制相机。
4. 联调心率/踏频/相机共存、无线调度、资源占用及掉线恢复，再考虑刷写和功耗优化。

## 来源与许可

心率发现流程的原始 Apache-2.0 署名保留在 `src/main.c`，许可证在 `LICENSES/Apache-2.0.txt`。Nordic SDK、ANT 协议栈、网络密钥及原厂固件不存入本仓库。ANT 沿用原工程的个人非商业评估配置；本目录不是扩大其许可范围的声明。

认证消息使用 NCS 固定的 Nanopb 提交 `7307ce399b81ddcb3c3a5dc862c52d4754328d38`，许可见 `LICENSES/Nanopb.txt`，云端生成 C 文件，不提交生成产物。`miwear_auth.proto` 是按公开线路字段独立定义的最小子集，依据为 AstroBox Pb 提交 `03a92010056dd41af114f6f46fd612104b27bd7b` 的 wear / wear_account 定义；不复制完整上游模式或 Rust 实现。固定缓冲分别约束随机数、校验值、设备名称和加密设备描述，解析还核对 type/id/消息分支及确认结果。尚无在线认证状态机或绑定变更操作。

`src/s4_link.[ch]` 新增单台 S4 连接的逻辑所有权和引用管理：最后一个使用者退出前保留连接，不向地址不匹配、已断开或已持有连接的使用者重复授予引用。当前仅有组件与顺序测试，尚未接入心率/诊断生命周期；后续必须等 GATT 退订或取消完成后才能复用相应参数。组件通过不等于 HRS/FE95 同连接共存已验收。

`src/miwear_session.[ch]` 是离线测试中的认证状态机：新鲜随机数 → 校验手表 HMAC → 加密 companion 描述并构造确认 → 等待明确确认。传输忙时只保留一条待发消息，超时、失败或关闭时清除临时密钥；没有在线调用入口、真实密钥导入或持久化。调用者必须先完成 SAR，并提供 CSPRNG 随机数；PSA 初始化和所有会话操作须在合适栈大小的串行工作上下文中执行，不能在 GATT 接收回调里直接做密码计算。

配套描述中的 CCM 与后续应用 L2 加密应分别核对：固定 Core 源码的认证描述使用 CCM，而应用 `V2L2Cipher` 使用 CTR，不能把当前 CCM helper 直接套到应用消息上。仍待真实会话验证，不提供加密失败后的明文降级。
