# 心率 ANT+ 与相机中转组合固件

目标是在同一块 Pro Micro nRF52840 上保留手表心率 → ANT+、踏频触发及待机行为，并加入 S4 快应用 → Action 4 控制。两项功能需要链接为一个应用，不能依次刷入两个 UF2。

## 当前阶段

已导入用户实测工程的固件源码基线，来源提交及逐文件摘要见 `upstream.json`；原始 `watch-hr-ant-relay` 仓库不修改、不覆盖。保留原时钟、ANT 设备号 4242、踏频唤醒、心率过期处理和分区。组合副本先将 BLE 连接预算设为 3，并使心率连接回调及断开操作只处理自身连接，避免影响将来的相机或配套连接。

**这仍是组合开发基线，相机控制尚未接入，不能作为双功能完成版刷写。** `../protocol/miwear_auth.c` 参与编译但尚未从运行流程调用，不含用户 AuthKey。已有独立 probe 只作为协议诊断工具，不替换板上 ANT+ 应用。

## 组合内的只读诊断

新增 USB 文本命令，每条以回车结束；原来的单字节 `B` 进入启动盘命令保留。输入每轮最多处理 32 字节，不在 ANT 主循环等待整行。诊断不主动配对、不写 GATT、不控制相机，不自动选择附近设备。

```text
watch scan
watch stop
watch attach
watch connect AA:BB:CC:DD:EE:FF random
watch services
watch chars
watch channel
watch unchannel
watch disconnect
```

`watch attach` 复用现有心率连接；指定地址连接也优先复用匹配连接。反方向上，踏频唤醒心率功能时优先复用已选手表的配套连接。心率待机或超时不会主动断开仍被配套端占用的链路，待机时忽略心率数据；配套端退出后，闲置链路由主循环收尾。这里保持 HRS 订阅对象直到物理断开，避免待机时退订后立即重用参数。诊断发现未完成时拒绝手动分离。真实断线仍清空两端所有权，错误恢复的实机行为待验证。

`watch channel` 在已选连接中发现 FE95，核对 0050 的读取属性、005E 的通知属性和 005F 的无响应写入属性，在 005E 自己的描述符范围内查找 CCC，读取 0050 后才订阅通知。适配层用独立工作队列，支持最多 4 个完整帧的有界发送和 MTU 分块；目前 USB 命令只打开通道，不发送认证或应用数据。`watch unchannel` 请求关闭，必须等在途请求/退订的终止回调完成才释放引用并允许重新打开；关闭期间拒绝诊断分离和并行枚举。没有把取消请求当作可立即复用参数的信号，参照 [Zephyr GATT 生命周期约定](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__gatt__client.html)。

通道就绪后新增 `watch auth <32位十六进制AuthKey>`，仅通过本地 USB 使用，不要把真实值放进脚本参数、日志、代码或云端产物。接收命令后清除 USB 行缓冲，密钥只进入一次性 RAM 槽；协议线程生成新的随机挑战，再串接 SAR、L2、挑战验证和明确设备确认。失败/断开清除密钥，不自动重试。跨连接代次的排队数据不能发送到新连接。认证成功只证明配套协议已认证；应用身份路由和相机控制尚未接入。

## 指示灯

应用接管板载 PWM 指示灯：启动先熄灭，每 10 秒仅弱亮 100 毫秒，亮起时为 1kHz、2% 占空比；使用 GPIO 别名确定有效电平，避免沿用通用板 PWM 别名相反的极性。不修改 Bootloader、UICR 或原心率工程。实际亮度仍需在红板上观察。

只连接用户核实的实际手表地址，类型按广播中的 public/random 选择。扫描候选条件为 S4 名称、FE95 或 HRS，条件本身不能证明设备身份。等连接成功再枚举服务，等完成后再枚举特征，核对完整 UUID 与权限。8df62b6 的该命令集已通过组合云端构建，并在本机 S4 实测发现 FE95、0050/005E/005F 和同连接中的 HRS；不代表认证或应用通道已接通。心率仍按原踏频策略触发，诊断需求独立登记。

## 构建与验证

云端使用与实测心率工程一致的 NCS 3.2.4、ANT Add-on 2.1.1 及官方工具链镜像。该 SDK 配对符合 [ANT 官方兼容表](https://ant-nrfconnect.github.io/doc/compatibility.html)；没有因上游 Zephyr 更新而单独升级其中一个组件。本地不编译，不自动刷写。

保留显式静态分区表，云端对 UF2 地址、芯片 family、初始栈及复位入口进行检查。产物和元数据会明确标记相机控制未实现、组合真机未验收。

## 来源与许可

心率发现流程的原始 Apache-2.0 署名保留在 `src/main.c`，许可证在 `LICENSES/Apache-2.0.txt`。Nordic SDK、ANT 协议栈、网络密钥及原厂固件不存入本仓库。ANT 沿用原工程的个人非商业评估配置；本目录不是扩大其许可范围的声明。

认证消息使用 NCS 固定的 Nanopb 提交 `7307ce399b81ddcb3c3a5dc862c52d4754328d38`，许可见 `LICENSES/Nanopb.txt`，云端生成 C 文件，不提交生成产物。`miwear_auth.proto` 是按公开线路字段独立定义的最小子集，依据为 AstroBox Pb 提交 `03a92010056dd41af114f6f46fd612104b27bd7b` 的 wear / wear_account 定义；不复制完整上游模式或 Rust 实现。固定缓冲分别约束随机数、校验值、设备名称和加密设备描述，解析还核对 type/id/消息分支及确认结果。尚无在线认证状态机或绑定变更操作。

`src/s4_link.[ch]` 新增单台 S4 连接的逻辑所有权和引用管理：最后一个使用者退出前保留连接，不向地址不匹配、已断开或已持有连接的使用者重复授予引用。当前仅有组件与顺序测试，尚未接入心率/诊断生命周期；后续必须等 GATT 退订或取消完成后才能复用相应参数。组件通过不等于 HRS/FE95 同连接共存已验收。

`src/miwear_session.[ch]` 是离线测试中的认证状态机：新鲜随机数 → 校验手表 HMAC → 加密 companion 描述并构造确认 → 等待明确确认。传输忙时只保留一条待发消息，超时、失败或关闭时清除临时密钥；没有在线调用入口、真实密钥导入或持久化。调用者必须先完成 SAR，并提供 CSPRNG 随机数；PSA 初始化和所有会话操作须在合适栈大小的串行工作上下文中执行，不能在 GATT 接收回调里直接做密码计算。

配套描述中的 CCM 与后续应用 L2 加密应分别核对：固定 Core 源码的认证描述使用 CCM，而应用 `V2L2Cipher` 使用 CTR，不能把当前 CCM helper 直接套到应用消息上。仍待真实会话验证，不提供加密失败后的明文降级。

现已增加应用 PB 编解码及 L2 包装模块：PB 信道 1、认证 write=1、应用 encrypted-write=2。应用收发仅在认证状态 READY 时允许，使用方向对应的会话密钥与参考实现一致的 CTR IV；不是 CCM，也没有明文降级。CTR 不提供完整性保护，后续仍需验证 PB、应用包名/指纹、会话和命令票据。参照固定版本的 [L2 格式](https://github.com/AstralSightStudios/AstroBox-NG-Module-Core/blob/dc08a079501b3ca7dd9215727ccbc348278914fc/src/device/xiaomi/packet/v2/layer2.rs)与 [方向密钥/IV](https://github.com/AstralSightStudios/AstroBox-NG-Module-Core/blob/dc08a079501b3ca7dd9215727ccbc348278914fc/src/device/xiaomi/packet/cipher.rs)，未接入实机 GATT 收发。

## 相机侧发现（只读）

新增 USB 行命令 `camera scan` / `camera stop`。复用共享扫描调度器 RADIO_CAMERA，扫描最多 10 秒，最多打印 8 个不同地址的候选，相机侧停止不会撤销心率/手表的扫描请求。候选匹配沿用 Android `DjiBle.isDji` 的厂商广播字段；名称只供辨认，候选不等于已确认型号或获得授权。本阶段没有相机连接、配对、GATT 写入或快门行为，尚未刷入板上。

完整接入将依次验证 FFF0 服务、FFF4 通知、FFF5 写入，再移植现有 DjiSession 的 0x00/0x19 授权握手。新开发板控制器需要独立、可持久化的 controllerId 与六字节身份，不能借用手机身份伪装已授权；只在相机明确授权成功后保存设备及授权成功标记。已授权重连仍需握手，未获准自动选定附近其他相机。
